# Zenodo fragment-label audit

Source: Michelle Ernst, *Data for publication: Fragment to Framework:
Bottom-Up Engineering of the Band Gaps in Covalent Organic Frameworks*,
Zenodo record 14855145, version 1, CC BY 4.0.

## Decision

The release is sufficient to start both delta-learning calibration and a
direct fragment surrogate without generating new PBE0 labels.

`COFsalldata_forplots.csv` contains 315 COFs and, for every COF, separate PBE0
HOMO, LUMO, and HOMO-LUMO gaps for the node, linker, and node+linker system.
The example ORCA output identifies the method as PBE0-D3ZERO/def2-TZVP.

## Label inventory

| Role | Label occurrences | Unique role-specific SMILES | Matching local XYZ occurrences |
|---|---:|---:|---:|
| Node | 315 | 113 | 261 |
| Linker | 315 | 121 | 261 |
| Node+linker | 315 | 247 | 225 |
| Total | 945 | 481 role/SMILES pairs | 747 |

There are 443 unique canonical SMILES across all roles. The 945 occurrences
must not be treated as 945 statistically independent molecules because many
node and linker structures repeat across COFs. Cross-validation must group by
canonical fragment identity and preferably also by COF/building-block family.

## Geometry qualification

The Zenodo record includes calculation files and geometries only for COF 1.
It is a label table, not a complete per-fragment geometry archive. However,
747 of the 945 label occurrences have matching local deCOFpose XYZ files in
`DFT_cof_bandgap/fragments`. Fingerprint/RDKit surrogate training needs only
the released SMILES. Missing xTB geometries can be created from those SMILES
or regenerated by the existing DFT-free fragmentation pipeline.

## Generated files

- `per_fragment_pbe0_labels.csv`: normalized occurrence-level training table.
- `unique_fragment_pbe0_labels.csv`: role-specific canonical-SMILES summary.
- `inventory.json`: machine-readable counts.
- `record.json`: Zenodo API metadata and checksums.

All downloaded files with published MD5 values passed checksum verification.
